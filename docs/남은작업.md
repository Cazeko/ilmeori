```
규칙  대화 N건 중 기한·질문·결정 대기 표현이 있는 것을 고른다  →  근거 (사람·날짜·원문)
모델                                                        →  그 근거만으로 문장을 만든다
```

지킬 것 셋.
1. **근거를 고르는 일은 규칙이 한다.** 모델이 고르면 왜 골랐는지 화면에 적을 수 없다.

## 이번에 붙인 것 (2026-08-07 오후)

### 1. 인계서가 대화를 읽는다

`handover-draft.ts` 는 문서·이력·첨부만 읽고 **대화(comment)는 한 줄도 읽지 않았다.**
그래서 「1-다. 현안사항 및 문제점」은 문서 항목 제목에 "현안"이나 "유의"가 들어 있을 때만
채워졌고, 없으면 "확인된 현안사항이 없습니다"로 끝났다.

그런데 인계 대상 업무에는 이런 대화가 붙어 있다.

> "2027년도 예산 요구서에 대행료를 반영해야 하는데, 최종보고가 8월 14일이면 요구서 제출 기한과 겹칩니다."

**이게 정확히 현안사항이다.** 제품이 "왜 그렇게 정했는가는 대화에 있다"고 화면에서 말해 놓고
인계서는 그 대화를 통째로 건너뛰고 있었다 — 논지의 심장이 비어 있었던 셈이다.

방식은 **뜻을 판정하지 않고 표현을 찾는 것**이다. 기한·질문·결정 대기·이견·약속 다섯 갈래의
표현을 찾고, 고른 이유를 이름표로 함께 적고, **요약하지 않고 원문 그대로 인용**한다.
규칙이 왜 이 대화를 골랐는지 화면에 그대로 적을 수 있어야 하기 때문이다.

```
· 2026년 음식물류폐기물 수집·운반 대행 원가산정 용역
  [문서 — 4. 현안 및 유의사항]
  ...
  [대화 — 배도현 주무관, 2026년 7월 30일 · 기한 · 질문]
  "2027년도 예산 요구서에 대행료를 반영해야 하는데, ..."
```

근거 꼬리표에는 **몇 건 중 몇 건인지** 적는다("대화 10건 중 … 2건"). "대화에서 뽑았습니다"만
적으면 나머지를 읽지 않아도 된다는 뜻으로 읽힌다.

곁들여 고친 것: 업무 한 건마다 `getWorkDocument()` 를 세 번씩 부르고 있었다. 한 번으로 모았다.

### 2. 인계서 인쇄 서식

`@media print` + 인쇄 전용 문서(`print-sheet.tsx`). 브라우저 인쇄로 별지 제12호서식 모양 A4가 나온다.
구분·소속·직급·성명 표, 항목 일곱 개, 인계자·인수자·입회자 서명란, 맨 아래 출처 한 줄.

화면용 카드에 인쇄 규칙을 덧씌우지 않고 **두 벌을 따로 그린다.** 화면은 확인하는 도구이고
종이는 결재에 올리는 문서라 필요한 것이 다르다 — 화면에는 항목마다 근거 꼬리표가 붙어야 하고,
종이에는 그것이 서식을 어지럽힌다. 한쪽에 맞추면 반드시 다른 쪽이 어색해진다.

인쇄 버튼은 `window.print()` 말고는 방법이 없어 이 제품에서 **유일하게 스크립트가 필요한 곳**이다.
그래서 스크립트가 살아 있을 때만 그린다(`useSyncExternalStore`). 없으면 버튼이 아예 나타나지
않고 「Ctrl+P」 안내만 남는다 — 눌러도 아무 일도 안 하는 버튼보다 낫다.

### 3. 「이 업무가 보이는 이유」와 같은 주소·다른 계정

접근제어는 잘 돌수록 화면에 아무것도 보이지 않는다. 잘 막혀 있다는 것은 아무 일도 일어나지
않는다는 뜻이라서 그렇다. RLS 67개는 발표자료의 문장이고, 문장은 열세 팀이 다 쓴다.

업무 상세에 접히는 한 줄을 뒀다. 판정 순서는 `app.can_read_work()` 와 **같다.**

> **이 업무가 보이는 이유** — 참여자(열람)로 추가되어 있습니다
> 공개 범위가 「부서 공개」라, 자원순환과 직원과 참여자 3명에게만 열립니다.
> [이 주소를 다른 계정으로 열어 보기]

버튼을 누르면 세션이 끊기고, 계정을 고르면 **같은 주소로 돌아온다.** 볼 수 없는 계정으로 오면
「없습니다」가 뜬다. 새 질의는 0건이다 — 화면에 이미 온 데이터로만 문장을 만든다.

### 곁들여 잡은 것

| 무엇이 잘못돼 있었나 | 어디서 잡았나 |
|---|---|
| **`notFound()` 는 스크립트를 끈 브라우저에서 빈 화면이 된다.** 응답은 404인데 `<body>`가 비어 있고 본문은 `__next_f` 스크립트 안에만 있었다. 상위 레이아웃이 먼저 흘러 나간 뒤라 Next가 HTML로 못 그린다 | 브라우저 시험 |
| **`safeNext` 가 오픈 리다이렉트를 막지 못했다.** `/%09/evil.example.com` 이 검사를 통과했다 — 브라우저 URL 파서는 해석 전에 탭·개행을 **지우고** 읽는데, 검사는 지우기 전 문자열을 보고 있었다. Location 헤더에 원문이 실려 나가 프로토콜 상대 URL이 됐다 | 코드리뷰 → 실측 |
| 실제 프로젝트의 `handover.ai_model` 이 아직 `claude-opus-5` 였다. 시드를 고쳤지만 `on conflict do nothing` 이라 이미 들어간 행은 그대로였다 | 인쇄 서식 실측 |
| 인쇄 버튼이 화면에 **둘** 있었다 | 브라우저 시험 |
| 「없거나 보이지 않습니다」가 **목업 모드에서도** RLS를 근거로 댔다. 그 모드에는 Supabase가 아예 없다 | 코드리뷰 |
| 인쇄본 맨 아래 「생성 08:40」이 실제 조립 시각과 달랐다. 본문은 인쇄할 때마다 다시 조립되므로, 그 사이 붙은 대화가 실리면서 시각만 옛것이 찍혔다 | 코드리뷰 |
| 근거 꼬리표의 「언급된 N건」이 업무별 상한(3건)에 걸려 빠진 것을 세지 않았다. 잘라 놓고 말하지 않으면 「다 실었다」로 읽힌다 | 코드리뷰 |
| 인계 대상이 0건이면 「1-가·1-나」가 제목만 남고 본문이 통째로 비었다 (다른 과 인수자 + 부서 공개 업무) | 코드리뷰 |
| 「고칠 수 없는 업무입니다」의 「이 주소 다시 열기」가 편집 주소가 아니라 상세 주소로 갔다 | 코드리뷰 |
| `0001_schema.sql` 이 아직 「AI가 생성한 초안 · 생성 모델 기록」이라고 적고 있었다 | 코드리뷰 |

`notFound()` 건은 **응답 코드와 사람이 읽을 화면을 맞바꾼 것**이다. 페이지가 직접 그리면
스크립트 없이도 보이지만 응답은 200이 된다. 이 주소는 사람이 눈으로 여는 화면이지 기계가
부르는 API가 아니라서 이쪽을 골랐다. 없는 업무와 못 보는 업무를 구분하지 않는 것은 그대로다.

`safeNext` 건은 **검사하는 문자열과 이동하는 문자열이 서로 달랐던 것**이 원인이다.
같은 실수가 다시 나지 않도록 `tests/safe-next.test.mjs` 를 붙이고 `npm run check` 에 넣었다.
제출물에 깃헙 주소와 배포 주소가 함께 들어가므로, 심사위원을 외부 사이트로 보내는 링크 하나면
그걸로 끝이다.

### 검증

```
npm run check          타입 · safeNext 회귀 · 마이그레이션 · RLS 67개 · 시드 · 되돌리기
npm run test:browser   자바스크립트를 끈 브라우저 왕복 73건
```

`test:browser` 는 playwright 가 필요해서 저장소 의존성에는 넣지 않았다
(없으면 설치 방법을 안내하고 그냥 끝난다). 돌리는 법은 파일 맨 위에 적어 두었다.
**반드시 새로 빌드한 것을 띄우고 돌린다** — `next start` 는 뜰 때의 빌드를 붙들고 있어서,
고치고도 옛 화면을 보며 한참을 헤매게 된다.

코드리뷰는 다섯 관점(초안 정합성 · 보안 · 인쇄 · 문구 정직성 · 회귀)으로 나눠 돌리고,
나온 것을 다시 반박해 살아남은 것만 고쳤다. **36건 보고 → 16건 확정 → 전부 수정.**
반박되어 죽은 20건에는 「인계일에 인쇄한 날짜가 찍힌다」처럼 이미 고쳐진 것,
「220자 절단이 결론을 자른다」처럼 입력 상한(240자)이 이미 막고 있는 것이 섞여 있었다.
