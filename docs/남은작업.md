| 문서·업무 공동편집 | ❌ | 읽기만 된다. 섹션 잠금도 **표시만** |
| 진행상태 관리 | ✅ | 상태 변경 동작, 칸반 보드 |

## 반드시 해야 하는 것 (1차예선 전)

우선순위 순서다. 위에서부터 자르면 된다.

### 1. 참여자·권한 관리 — 0.5일

과제 요구사항에 **명시된** 항목인데 지금 읽기 전용이다.

- 참여자 추가 / 역할 변경(소유·편집·열람) / 제거
- 공개 범위 변경(참여자만 · 부서 공개 · 전체 공개)

DB 정책은 이미 다 있다. `work_member_insert/update/delete` 는 소유자만, 마지막 소유자는 트리거가 지킨다.

> **발표에서 값어치가 크다.** 권한을 바꾸고 다른 계정으로 전환하면 보이는 업무가 실제로 달라진다. RLS가 그림이 아니라 실제로 도는 증거가 된다.

### 2. 업무 만들기·고치기 — 0.5일

지금은 시드로 넣은 업무만 있다. 심사위원이 직접 업무를 만들어 볼 수 없다.

- 업무 생성(제목·설명·부서·마감·공개범위)
- 제목·설명·마감일 수정
- 「작년 이맘때」 연결 지정

### 3. 문서 항목 편집 + 잠금 — 1일

「문서 공동편집」이 요구사항 1번인데 지금 못 고친다. 잠금은 화면 표시만이고 실제로 잡히지 않는다.

- 항목 편집 → 저장 (저장할 때마다 판이 남는 트리거는 이미 있다)
- 편집 시작하면 잠금, 5분 뒤 자동 해제 (DB 정책 완성됨)
- 항목 추가·삭제

### 4. 첨부파일 — 1.5일

지금은 경로만 있고 파일이 없다. **이게 「문서」의 현실이다** — 공무원은 hwp로 일한다.

- 업로드 / 내려받기 (private 버킷 + 단기 만료 링크, 정책 완성됨)
- **같은 문서의 새 판 올리기** ← 핵심
  `계획_최종_진짜최종_교통과반영.hwp` 문제를 없애는 것
- 판별 이력: 누가 언제 어떤 판을 올렸나

> 브라우저에서 hwp를 **편집**하는 것은 불가능하다. 한컴이 API를 열지 않고,
> docx도 문서 서버(OnlyOffice 등)가 따로 필요해 Vercel에 올릴 수 없다.
> 우리 주장은 "한글을 대체한다"가 아니라 **"한글 파일 사이의 맥락을 붙잡는다"** 여야 한다.

### 5. AI 실제 연결 — 1일 🔴

`src/lib/handover-draft.ts` 는 **규칙 기반 조립**이다. Claude를 부르지 않는다.
그런데 화면에는 「이 초안은 AI가 만들었습니다 · 모델 claude-opus-5」라고 떠 있다.

**질의응답에서 "어떤 모델 쓰셨어요?" 한 마디에 무너진다.** 셋 중 하나를 골라야 한다.

| | 내용 |
|---|---|
| A | 실제로 Anthropic API를 붙인다 |
| B | 문구를 정직하게 바꾼다. "쌓인 기록에서 자동으로 뽑았습니다" (과제는 AI 필수가 아니다) |
| **C** | **규칙으로 뼈대를 뽑고 AI가 문장만 다듬는다.** 근거 추적은 규칙이라야 정확하고, AI도 진짜가 된다 |

### 6. 배포 — 0.5일

Vercel + 환경변수 3개. 지금 쓰는 터널 주소는 세션이 끝나면 죽는다.
제출물에 「배포된 웹앱 주소」가 포함되므로 이건 마감 전 필수다.
