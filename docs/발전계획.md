## 3. 결재 — 데이터 모델 (8/8~9)

### 3.1 마이그레이션

**`0016_approval.sql`**

기존 규약을 따른다 — **표와 열거형은 스키마 없이(`public`), `app`은 RLS 보조 함수 전용**이다.

```sql
-- 직급 서열. 결재선 자동 생성이 이 한 칸에서 나온다.
-- profile.position(주무관/팀장/과장)은 표시용 문자열이고, 서열 판정은 숫자로 한다.
alter table profile add column rank smallint not null default 50;
-- 10 시장 / 20 국장·실장 / 30 과장 / 40 팀장 / 50 주무관

create type approval_kind as enum (
  'draft',        -- 기안
  'review',       -- 결재   (중간결재자)
  'final',        -- 최종결재
  'delegated',    -- 전결
  'acting',       -- 대결
  'concur_seq',   -- 순차협조
  'concur_par',   -- 병렬협조
  'post_report'   -- 사후보고
);

create type approval_state as enum (
  'drafting',     -- 기안 중 (임시저장)
  'in_progress',  -- 진행
  'completed',    -- 완결
  'rejected',     -- 반려
  'withdrawn'     -- 회수 (기안취소)
);

create table approval (
  id            uuid primary key default gen_random_uuid(),
  work_id       uuid not null references work(id) on delete cascade,
  form          text not null,          -- 'report' | 'plan' | 'review' | 'cooperation'
  doc_no        text unique,            -- HS-협조-20260808-0001
  title         text not null,
  body          text not null default '',
  retention     smallint,               -- 보존연한(년)
  security      text not null default 'normal',
  state         approval_state not null default 'drafting',
  drafter_id    uuid not null references profile(id),
  created_at    timestamptz not null default now(),
  -- 결재가 끝난 시각. 「completed_at」이라 이름 붙이면 반려된 문서의 그 칸이 거짓말을 한다.
  closed_at     timestamptz
);

create table approval_step (
  id           uuid primary key default gen_random_uuid(),
  approval_id  uuid not null references approval(id) on delete cascade,
  seq          smallint not null,       -- 결재 순서
  kind         approval_kind not null,
  approver_id  uuid not null references profile(id),
  position     text not null,           -- 서명 당시 직위 (나중에 바뀌어도 문서엔 그대로)
  signed_at    timestamptz,
  rejected_at  timestamptz,             -- 누가 반려했는지도 칸에 남는다
  opinion      text,                    -- 「의견 있음」 — 시행규칙 제4조
  unique (approval_id, seq),
  unique (approval_id, approver_id)
);

-- 기안란은 한 문서에 하나뿐이다. 둘이면 상신 절차가 아무거나 집어 서명하고,
-- 남은 기안란은 아무도 처리할 수 없어 그 문서는 영원히 완결되지 않는다.
create unique index on approval_step (approval_id) where kind = 'draft';
```

> **`position`을 문자열로 박는 이유.** 결재란은 서명한 그 시점의 직위를 남긴다.
> `profile`을 조인해 그리면 인사이동 후에 옛 문서의 결재란이 바뀐다. 그건 문서 위조다.

> **계획과 달라진 것 셋.** `completed_at` → **`closed_at`**(반려된 문서의 칸이
> 거짓말을 하지 않게), `rejected_at` 추가(반려한 사람이 칸에 남게),
> 기안란 부분 유니크 인덱스 추가(검토에서 구멍으로 나왔다).

**`0017_approval_rls.sql`** — 실제로 들어간 모양

- `approval` 읽기: 기안 중이면 기안자만. 상신된 뒤에는 그 업무를 볼 수 있는 사람
  ∪ 결재선에 이름이 있는 사람. **협조자는 업무는 못 봐도 그 문서 한 장은 본다**
- `approval_step` **UPDATE 정책도 권한도 없다.** 서명이 들어가는 길은 절차 넷뿐이다 —
  `submit_approval` · `sign_approval` · `reject_approval` · `withdraw_approval`
  (계획에서는 「자기 칸만 UPDATE」였다. 완결 판정이 두 표에 걸쳐 있어 절차로 옮겼다)
- **완결·반려·회수된 결재는 아무도 못 고친다** — `0011`의 완료된 인계 잠금과 같은 규칙
- **상신된 결재의 본문은 얼어붙는다.** 서명한 사람이 읽지 않은 글에 서명한 것이 되면 위조다
- 결재 사건은 기존 `activity`에 얹는다. 새 이력 표를 만들지 않는다
- 기안 중인 문서는 실시간 신호를 보내지 않는다 — 초안을 쓰고 있다는 사실 자체가 정보다

### 3.2 결재선 자동 생성

```
기안자 → 같은 부서에서 rank가 더 작은 사람을 위로 훑는다
       → 팀장(40) · 과장(30) · 국장(20)
       → 마지막 사람을 'final', 중간을 'review'
협조 부서를 고르면 그 부서의 같은 급을 'concur_seq' 로 끼워 넣는다
```

자문의 *"급을 맞추어 협조"* / *"검토 후 협조"* 두 방식을 옵션으로 둔다.

### 3.3 결재선 복사

*"다른 부서 사람들이 결재한 거 그대로 쓰기 기능, 무조건 있어야 하고"* — 자문에서 「무조건」이 붙은 유일한 요구다.

- 내가 볼 수 있는 결재 문서 목록에서 하나 골라 결재선만 가져온다
- 사람이 그대로 있으면 그대로, 부서가 다르면 **같은 rank의 사람으로 치환**해 제안한다

### 3.4 행동시험 (`supabase/rls.test.mjs`에 [15] 추가)

```
[15] 결재
  · 결재선에 없고 업무도 못 보면 결재 문서가 보이지 않는다
  · 남의 결재칸에 서명할 수 없다
  · 완결된 결재는 기안자도 못 고친다
  · 전결이 찍히면 그 뒤 순서는 서명할 수 없다
  · 문서번호는 중복되지 않는다
```

### 4.1 `/approvals` 결재함

네이버웍스 결재 IA를 그대로 따른다. 공무원이 이미 아는 모양이라 학습 비용이 0이다.

```
┌──────────────┬──────────────────────────────────────┐
│ [ 결재 올리기 ]│  결재 문서                            │
│              │  ┌── 대기 ────────┐ ┌── 진행 ──────┐ │
│ ⧗ 대기   3   │  │ …               │ │ 진행 중 3/5  │ │
│ ◷ 예정       │  └────────────────┘ └──────────────┘ │
│ ⚖ 처리       │                                       │
│ ☑ 완료       │  최근 사용 서식        즐겨찾는 서식   │
│ ⊡ 전체       │  [보고서][계획서][검토서][업무협조]    │
└──────────────┴──────────────────────────────────────┘
```

- 좌측 트리는 링크다. 주소에 상태가 남고 자바스크립트 없이 돈다 (기존 필터와 같은 규약)
- **대기에만 숫자 배지** — 그것만이 지금 내가 해야 할 일이다
- 서식 그리드가 *"바빠 죽겠으니 빠바바밥"* 에 대한 답이다

### 4.2 결재란 (`components/approval/approval-grid.tsx`)

flex·네이버웍스·하이웍스 세 제품이 공통으로 쓰는 문법이다. 다르게 그릴 이유가 없다.

```
┌──────┬─────────┬─────────┬─────────┬─────────┐
│      │  주무관  │  팀장    │  과장    │  국장    │
│ 결재  │  김민준  │  이서연  │  전결    │    ╲    │
│      │  8/8    │  8/9    │  8/10   │         │
├──────┼─────────┴─────────┴─────────┴─────────┤
│ 협조  │  건축과 박도윤 8/9  ·  회계과 (대기)     │
└──────┴───────────────────────────────────────┘
```

- 전결권자 칸에 **「전결」**, 그 뒤 칸에는 사선
- 서명은 이름 + 날짜. 필기체 이미지나 도장 그림은 쓰지 않는다 — 시제품에서 도장은 위조 인상을 준다
- **「의견 있음」**이 있으면 이름 옆에 표시하고 본문 아래에 그 의견을 편다 (시행규칙 제4조)

### 4.4 업무 상세에 `결재` 탭

탭이 4개에서 5개가 된다 — `문서` `대화` **`결재`** `이력` `참여자·권한`.

> **계획과 달라진 것 하나.** 계획은 「한/글로 만든 템플릿을 열어 자리표시자만 치환」이었다.
> **그 길을 못 갔다** — 이 저장소에는 한/글이 없어서 템플릿 자체를 만들 수 없다.
> 그래서 **OWPML 을 직접 조립**했다. 계획이 피하려던 위험(「우리 XML이 유효한가」)을
> 그대로 안게 되었으므로, 대신 두 가지를 했다.
>
> | | 실제 |
> |---|---|
> | JSZip 의존성 | **안 넣었다.** 필요한 것은 STORED 와 DEFLATE 둘뿐이고 `node:zlib` 에 있다. 아이콘도 같은 이유로 손으로 구웠다(`scripts/gen-icons.mjs`) |
> | 검증 | `npm run test:hwpx` **57건** — ZIP 규격(mimetype 선두·무압축·CRC32), python `zipfile.testzip()`, `xmllint` 로 XML 여섯 장, 참조 itemCnt 대조, 표의 colSpan 합, **본문에 섞인 `<`·`&`·제어문자**, 서로게이트 경계, 같은 문서는 같은 바이트 |
> | 폴백 | **선언하지 않고 살려 두었다.** 결재 문서에도 인쇄(A4)를 붙였고 화면이 그 사실을 적는다 |
> | 시험이 못 하는 것 | **「한/글에서 열린다」는 증명하지 않는다.** 셋 중 하나라도 깨지면 한/글은 반드시 못 열지만, 셋이 통과한다고 열린다는 보장은 없다 |
>
> 한 파일에 몰아넣은 이유도 적어 둔다 — `pack.ts` 는 바깥을 하나도 부르지 않아서
> 시험이 TS 를 그대로 불러 돌릴 수 있다(Node 22의 타입 벗기기). 이 제품에서
> **바이트를 직접 쓰는 유일한 자리**라 그 자리만은 눈으로 확인할 수 있어야 했다.

### 5.1 방식 — 만들지 않고 갈아 끼운다 (→ 직접 조립으로 바뀜)

```
한/글로 만든 별지 제2호서식 템플릿.hwpx
        │  (ZIP)
        ├─ Contents/section0.xml   ← 여기의 자리표시자만 치환
        ├─ Contents/content.hpf
        └─ …
        │  JSZip 으로 열고 → 치환 → 다시 압축
        ▼
    완성된 .hwpx  →  한/글에서 열린다 (템플릿이 보장한다)
```

**직접 생성하지 않는 이유.** OWPML 명세를 우리가 맞게 썼는지는 한/글로 열어 봐야만 안다.
템플릿 치환이면 검증 문제가 *"우리 XML이 유효한가"*에서 *"글자가 제자리에 들어갔나"*로 줄어든다.

| 후보 | 판단 |
|---|---|
| **템플릿 + JSZip 치환** | **채택.** 서식·표·머리글 보존. 의존성 하나 |
| `@ssabrojs/hwpxjs` | 평문 위주. 표·서식이 필요한 우리 용도엔 부족 |
| `hwpxlib`(Java) | 가장 성숙하나 백엔드 언어가 바뀐다 |

### 5.2 파일 — 실제로 만든 것

```
src/lib/hwpx/pack.ts        ZIP 포장 + OWPML 조립. 바깥을 하나도 안 부른다
src/lib/approval-export.ts  기록 → 근거 꼬리표 → 서식 칸 (handover-draft.ts 와 같은 구조)
tests/hwpx.test.mjs         53건
```

`buildHandoverDraft()`가 이미 하는 일과 같다. 대응표만 다르다.

### 5.3 검증 — **아직 끝나지 않았다** 🔴

기계가 지키는 데까지는 갔다.

```
npm run test:hwpx    57건 통과
  ZIP        mimetype 이 첫 항목·무압축, CRC32 규격값, python zipfile.testzip()
  XML        xmllint 로 여섯 장 전부, 본문의 <·&·]]>·제어문자가 파일을 안 깨뜨림
  참조       itemCnt 가 실제 개수와 같고, 본문이 쓰는 글자·문단모양이 전부 정의돼 있음
  표         행마다 colSpan 합 = 열 수, 칸 폭 합 = 본문 폭(48190)
  결정성     같은 문서를 두 번 만들면 바이트까지 같다
  이름       경로 탈출·제어문자·서로게이트 경계(80자 자리에 이모지가 걸쳐도 안 깨진다)
```

**남은 것은 사람이 한 번 해야 한다.**

1. 만든 파일을 **실제 한/글에서 연다** ← 이 저장소에는 한/글이 없다
2. 표가 깨지지 않는가 · 한글이 깨지지 않는가 · 편집이 되는가
3. 안 되면 **인쇄(A4) 폴백** — 이미 붙어 있으므로 그때 화면 문구만 바꾸면 된다

> **폴백을 미리 붙여 둔 이유.** 8/13에 파일이 안 열리는 것을 알게 되면 그날부터
> 종이를 만들어야 했다. 지금은 종이가 이미 있고, 화면·파일·종이가 **같은 모델**
> (`ApprovalExport`)에서 나오므로 어느 쪽이 죽어도 나머지가 같은 말을 한다.
> 「검증이 안 끝나면 이틀이 통째로 날아간다」던 위험이 여기서 사라졌다.

## 6. 「온나라로 넘기기」 (8/14) → **8/8 완료**

상신된 문서에서 한 번 누르면 HWPX가 떨어진다. 그리고 **근거 꼬리표가 문서에 실린다.**

```
2. 사전 검토 및 협의
   배도현 주무관 협조 완료 (의견 있음)
      └ 근거: 결재 협조란 서명 · 2026년 8월 7일
   “2027년도 예산 요구서 제출 기한(8/8)과 겹칩니다…”
      └ 근거: 시행규칙 제4조의 「의견 있음」

3. 관련 기록
   “…8월 8일까지 반영본을 받기로 했으니 그때 공유드리겠습니다.”
      └ 근거: 업무 대화 · 박준호 주무관, 2026년 7월 30일 · 약속
```

지금 인계서가 하는 것과 같다. 그리고 **이것이 온나라에도, 브리티웍스에도, 네이버웍스에도 없는 화면이다.**

> **계획과 달라진 것 넷.**
>
> | 계획 | 실제 |
> |---|---|
> | 「결재가 **완결된** 문서에서」 | **상신된 문서 전부.** 대신 진행 중이면 「서명이 덜 찍힌 결재란이 그대로 실립니다」라고 화면이 먼저 말한다. 기안 중인 문서는 화면과 주소 양쪽에서 막는다 — 번호도 서명도 없는 초안이 결재 문서 모양으로 나가면 그건 위조다 |
> | 파일만 | **화면·파일·종이 셋.** 셋이 같은 모델(`ApprovalExport`)에서 나온다. 하나라도 다른 말을 하면 근거를 붙이려고 만든 장치가 그 자리에서 거짓이 된다 |
> | — | **근거 고르는 규칙을 인계서보다 좁게 잡았다.** 인계서에는 「없는 것을 넣는 실수보다 있는 것을 빠뜨리는 실수가 비싸다」고 적었는데, 결재 문서는 건물 밖으로 나가므로 반대다. 실제로 「까지·일정·법」을 낱말로 잡았더니 *"정기인사로 이 업무를 이하람 주무관에게 넘기게 됐습니다"* 가 「기한」 근거로 결재 문서에 실렸다 |
> | — | **협조자(업무를 못 보는 사람)도 내보낼 수 있다.** 그 계정에서는 근거 자료가 비는데, 「없다」가 아니라 **「이 계정에서는 못 본다」**고 화면과 파일 양쪽에 적는다 |

## 7. 화면 정비 + PWA (8/15) → **8/8 완료**

앞서 논의한 디자인 건을 여기서 한꺼번에 친다.
**색 두 층과 본문 폭은 8/8에 먼저 쳤다** — 결재 화면이 새로 열두 개 붙는 김에 같이
바꾸는 편이, 나중에 화면 수가 더 늘어난 뒤에 손대는 것보다 싸다.

| 항목 | 내용 |
|---|---|
| ~~색 두 층~~ ✅ 8/8 | **`--color-white` 를 덮어쓰지 않았다.** Tailwind 는 `bg-white` 와 `text-white` 가 같은 토큰이라, 덮어쓰면 파란 버튼 글자까지 내려간다 — 재 보니 `bg-danger` 위 흰 글자가 4.56 → **4.37 로 미달**이었다. 판 전용 토큰 `--color-surface: #fafafa` 를 새로 두고 `bg-white` 55곳을 `bg-surface` 로 바꿨다. `--color-gray-5: #f0f1f2`. 인쇄는 `@media print` 에서 순백으로 되돌린다 |
| ~~본문 폭~~ ✅ 8/8 | `PageContainer` 신설. 폭이 셋이다 — `wide`(1440px, 목록·보드) · `doc`(4xl, 결재 문서처럼 읽는 화면) · `form`(3xl, 폼). **12개 화면 교체** |

| ~~제목~~ ✅ 8/8 | `PageHeader` h1을 `text-h2`(24px) → `text-h1`(32px). 좁은 화면에서는 24px 그대로 |

| ~~PWA~~ ✅ 8/8 | `app/manifest.ts` + `public/sw.js` + 아이콘 넉 장. **화면(HTML)은 한 줄도 캐시하지 않는다** — 아래 상자 참조 |

> **서비스워커가 하지 않는 일이 그 파일의 전부다.**
>
> 「셸 캐시만」이라고 적어 두었는데, 실제로 짜면서 그 선을 더 좁혔다.
> 공문서를 다루는 시스템이고 시청 자리의 컴퓨터는 여러 사람이 쓴다. 서비스워커가
> 화면을 캐시하면 그 문서는 **로그아웃한 뒤에도 디스크에 남는다** — 캐시는 쿠키가
> 아니라서 세션이 끊겨도 지워지지 않고, 다음 사람의 브라우저가 같은 출처에서 그것을
> 그대로 꺼내 쓸 수 있다.
>
> 그래서 담는 것은 **내용이 없는 것들뿐**이다 — 빌드마다 이름이 바뀌는 스크립트·스타일,
> 아이콘, 설명서, 그리고 「연결이 끊겼습니다」 한 장. 화면·RSC 응답·서버 액션·첨부·HWPX 는
> 한 줄도 안 담는다. **「오프라인에서 업무를 본다」는 할 수 있지만 하지 않는다.**
>
> 아이콘은 `scripts/gen-icons.mjs` 가 굽는다. SVG→PNG 도구가 전부 수십~수백 MB 라
> 넉 장 만들자고 넣지 않았다(HWPX 에서 ZIP 라이브러리를 안 넣은 것과 같은 판단).
> 사각형과 선분뿐이라 거리함수로 충분하고, 3×3 으로 훑어 가장자리를 다듬는다.
>
> ⚠ `manifest.webmanifest` 와 `sw.js` 는 **인증 쿠키 없이** 요청된다. `proxy.ts` 의
> matcher 에서 빼 두지 않으면 둘 다 `/login` 으로 튕겨, 설치는 「설명서를 못 읽는다」로
> 서비스워커는 「스크립트가 아니다」로 **조용히** 실패한다. CSP 에도 `worker-src 'self'` 를
> 못박았다 — 안 적으면 `script-src` 로 떨어지는데 거기 `'strict-dynamic'` 이 있어 막힌다.

~~대비 재계산이 필요하다~~ → **8/8에 측정하고 `globals.css` 주석에 수치를 적었다.**
판이 `#fafafa` 로 내려간 뒤 값이다.

전부 4.5:1 이상이라 `--color-status-*-text` 5종은 손대지 않았다. 대신 둘이 걸렸다 —

## 9. 발표에서 말할 순서

1. 문제 — 인사이동이 오면 일머리가 사라진다 (기존)
2. **"그런데 공무원은 협업 도구를 왜 안 쓸까요? 결재가 없으니까요."** ← 자문 인용
3. 그래서 결재를 넣었습니다. **다만 온나라를 대체하지 않습니다**
4. 시행규칙 제3조 — 별지 제1호(발신) vs **제2호(내부결재)**. 우리는 뒤쪽입니다
5. 시연 — 업무 협업 → 검토·협조 → **한글 파일로 떨어짐** → 온나라에 올리면 끝
6. 그리고 그 문서의 모든 문단에 **어느 기록에서 나왔는지가 붙어 있습니다**
7. 인계·인수 (기존 클라이맥스)

**가장 위험한 질문은 4번을 먼저 말하지 않았을 때 온다** — *"그거 온나라에 있는데요?"*
