# 화면 갈무리

`npm run build && npm start` 후 1440×900(모바일은 390×844)에서 자동 촬영한 것이다.
발표자료를 만들 때 이걸 그대로 쓰거나, 배포 후 같은 화면을 다시 찍으면 된다.

| 파일 | 화면 | 발표에서 쓰기 좋은 지점 |
|---|---|---|
| `01-login` | 들어가기 | 심사위원이 클릭 한 번에 도착한다는 것. 가상 데이터 고지 |
| `02-home` | 홈 (김서연) | 지연 1건이 맨 위에 뜨는 것 |
| `03-board` | 업무 보드 | 부서 간 협업(「6개 부서」 배지) + 지연 강조 |
| `10-board-overdue` | 지연만 필터 | 필터가 주소에 남아 그대로 공유된다 |
| `04-detail-doc` | 문서 탭 | **「정유진 편집 중」 섹션 잠금** |
| `05-detail-talk` | 대화 탭 | 부서 간 실제 협의가 업무에 붙어 있는 모습 |
| `06-detail-history` | 이력 탭 | **1순위 스크린샷.** 다섯 달치 협업이 자동으로 쌓인 기록 |
| `07-detail-people` | 참여자·권한 | 권한이 설명이 아니라 DB가 강제하는 값이라는 것 |
| `13-detail-prevyear` | 원가산정 용역 | **「작년 이맘때」 카드** |
| `12-handover-generated` | 인계 초안 | **2순위 스크린샷.** 항목마다 붙은 「근거:」 칩 |
| `15-handover-dialog` | 실행 확인 | 되돌릴 수 없는 동작 앞의 확인 |
| `16-handover-done` | 인계 완료 | 주담당이 실제로 바뀐 상태 |
| `17-haram-board`, `18-haram-people` | 인수자 시점 | 넘겨받은 사람이 곧바로 이력을 물려받는다 |
| `08-audit` | 열람기록 | 사용자에게 쓰기 권한이 없는 표 |
| `19`~`21` | 좁은 화면 | 반응형 + 모바일 서랍 |

`09-handover-none`은 인계 건이 없는 계정(김서연)에서 본 빈 화면이다.
빈 화면도 무엇을 하면 되는지 알려 준다는 것을 보이려면 쓸 수 있다.

> ⚠ 위 `01`~`21`은 **2026-08-06에 찍은 것이라 지금 화면과 다르다.** 색을 12개에서
> 4개로 줄이고 홈을 히어로 중심으로 다시 짜기 전의 모습이다. 발표에 쓰려면 다시
> 찍어야 한다. 굳이 남겨 두는 이유는 아래 실눈 판과 같다 — 무엇이 달라졌는지를
> 보이는 데 옛 판이 필요하다.

## 실눈 판 — `squint-*`

`npm run test:squint` 가 만든다(1440×1000, 첫 화면만). 1차예선 심사평의
「대시보드가 전부 평평해서 무엇을 봐야 하는지 눈에 안 들어온다」에 답하는 자료다.

| 파일 | 무엇 |
|---|---|
| `squint-home-blur-before` / `-after` | **1순위.** 흐리게 봤을 때 덩어리가 하나로 서는가 |
| `squint-home-sharp-before` / `-after` | 같은 화면의 또렷한 판 |
| `squint-works-blur-before` / `-after` | 업무 보드. 색을 걷어내자 지연 카드만 남는다 |

흐린 두 장을 나란히 놓는 것이 이 자료의 전부다. **고치기 전 판에서는 주황 띠와
네모 넷과 알록달록한 점들이 비슷한 무게로 흩어져 있고, 고친 판에서는 붉은
덩어리 하나가 혼자 선다.** 「디자인을 고쳤습니다」라고 말하는 것보다 이 두 장이 세다.

숫자로는 홈의 지배도가 **1.34 → 1.67** 로 올랐다(문턱 1.5). 지표를 어떻게 재는지와
왜 업무 보드는 판정하지 않는지는 `tests/squint.test.mjs` 머리글에 적혀 있다.
